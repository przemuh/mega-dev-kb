Problems and separate tickets

Shared parser reads month first

GitHub issue #1

The shared parser assumes month/day even when the tenant’s locale is day-first. The supplied classifier assigns app and email reports from day-first tenants here, along with form reports using booking-v2. For example, an intended 7 April becoming 4 July is a day/month swap.

Keep the parser fix separate from the form hint fix. Verify locale-aware parsing with ambiguous dates and unambiguous dates, and ensure app, email, and booking-v2 inputs agree.

booking-v3 date hint conflicts with tenant locale

GitHub issue #2

The booking-v3 form prints MM/DD/YYYY for day-first tenants, but reads the entered value using the tenant’s day-first order. People following that hint can get a swapped date even independently of the shared parser problem. The supplied tenant directory identifies Alder Physio, Copper Studio, and Pale Harbour as booking-v3 tenants.

Make the visible hint and accepted input format agree with the tenant locale. Verify the displayed hint, actual submission, and saved date together. App and email reports from these tenants still belong to the parser group; tenant identity alone is insufficient.
